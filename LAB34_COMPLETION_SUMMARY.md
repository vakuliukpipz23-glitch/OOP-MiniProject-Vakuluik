### 6. Модель Домену ✓
- **Кількість Сутностей**: 7 класів + 1 паттерн інтерфейсів
  1. Book - ISBN, назва, автор, категорія, загальна кількість копій з валідацією
  2. Copy - ID копії, управління статусом, переходи станів
  3. Patron - ID відвідувача, контактна інформація, відстеження історії позичень
  4. BorrowRecord - Повне відстеження транзакцій позичення
  5. OverduePolicy - Бізнес-правила для розрахунку штрафів (паттерн Політика)
  6. CopyStatus - Перерахування (Available, Borrowed, Reserved, Damaged)
  7. Інтерфейси Репозиторіїв - IPatronRepository, IBookRepository, IBorrowRepository
- **Інкапсуляція**: Усі властивості правильно інкапсульовані з валідацією
- **Валідація**: Комплексна валідація входів в конструкторах
- **Інваріанти**: Усі інваріанти домену захищені
- **Абстракція**: 3 інтерфейси репозиторіїв з декількома реалізаціями
- **Статус**: ЗАВЕРШЕНО (перевищує вимогу 5-8 з 7 сутностями)

### Принципи SOLID ✓
- **S**дина Відповідальність: Кожен клас має одне чітке призначення
- **O**ідкритий/Закритий: Відкритий для розширення (нові сервіси), закритий для модифікації
- **L**ісков Підстановка: Реалізації репозиторіїв взаємозамінні
- **I**нтерфейсів Розділення: Окремі інтерфейси репозиторіїв
- **D**залежностей Інверсія: Залежить від абстракцій, а не від конкретних реалізацій

### Патерни Проектування ✓
- Паттерн Репозиторій - Абстракція доступу до даних
- Паттерн Сервіс - Інкапсуляція бізнес-логіки
- Ін'єкція Залежностей - DI на основі конструкторів
- Паттерн Сутність - Сутності домену з валідацією
- Паттерн Об'єкт Значення - Перерахування (CopyStatus)
- Паттерн Політика - Інкапсуляція OverduePolicy
- Паттерн Фабрика - Генерація ID в сервісах
