# FINAL_REPORT

## Вступ
Цей проект є фінальним міні-проєктом на тему управління бібліотекою. Основна мета — показати завершений навчальний продукт з архітектурою, persistence, якістю коду та документацією.

## Архітектурне рішення
Проєкт реалізовано за шаровою архітектурою:
- Domain: сутності, валідація, бізнес-правила.
- Application: сервіси для use cases.
- Infrastructure: репозиторії, persistence та файловий доступ.
- Console: UI для взаємодії користувача.

Це рішення дозволяє тримати бізнес-логіку ізольованою від деталей збереження.

## Найважливіші рефакторинги перед релізом
- Виділення інтерфейсів репозиторіїв та сервісів для зменшення зв’язності.
- Уніфікація обробки помилок у сервісних методах.
- Винесення persistence в `LibraryPersistenceService` з `IDataStore<T>`.
- Додавання окремих методів у `Program.cs` для кожного меню, щоб зменшити складність головного циклу.

## Зроблені зміни для release hardening
- Додано перевірку на null і валідацію в конструкторах сервісів.
- Покрито бізнес-логіку тестами і додано негативні сценарії.
- Переклад документації на актуальний стан коду.
- Налаштовано CI на .NET 10 з coverage.
- Додано документальний план релізу.

## Проблеми та компроміси
- Використано JSON-файл для persistence, хоча ітерація 37 передбачає можливість SQL/REST у майбутньому.
- Консольний UI залишився простим, тому користувацький досвід мінімальний, але стабільний.
- Не реалізовано повноцінний audit/logging для кожної операції.

## Теми курсу, які найкраще демонструє проєкт
- SOLID і DDD-підхід у шаровій архітектурі.
- Колекції, LINQ та групування у звітності.
- Обробка помилок та negative scenarios.
- Persistence через абстракцію `IDataStore<T>`.
- Тестування: unit + integration tests.

## Теми, які можна докласти додатково
- Асинхронне batch save/load і import/export.
- Cache/Proxy для прискорення пошуку.
- Протоколи повідомлень або audit log через Observer.
- REST API або адаптер для нових джерел даних.

## Висновок
Поточний стан проєкту є релізно готовим для навчальної демонстрації. Збережено стабільну бізнес-логіку, додано персистентність, покрито тестами та підготовлено основну документацію для користувача й розробника.
