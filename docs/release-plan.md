# Release Plan v1.0.0

## Що входить у версію v1.0.0
- Робочий консольний додаток для управління бібліотекою.
- Персистентне збереження стану у файл `data/library.json`.
- Реєстрація відвідувачів, реєстрація книг, позичення та повернення.
- Механізм пошуку книг за назвою, автором та категорією.
- Аналітика: активні позичення, прострочені книги, борги та топ-позичуваних книг.
- Набір модульних та інтеграційних тестів з coverage.
- CI workflow на .NET 10 з автоматичним запуском тестів та збором coverage.
- Документація: user guide, developer guide, testing, release plan, final report.

## Що переноситься в “після курсу”
- Розширена багатокористувацька автентифікація/авторизація.
- Веб-інтерфейс або REST API.
- SQL або NoSQL базу даних для persistence.
- Повноцінний audit log або messaging (Observer/Decorator).
- Вбудована система рейтингу/відгуків.
- Реалізація кешування і Proxy на рівні сховища.

## Допустимий технічний борг
- Відсутність явної багатопотокової безпеки у in-memory репозиторіях.
- Базовий консольний UI без advanced UX.
- Простий формат збереження JSON без валідації схеми.
- Жорстко задані business policies у коді, без конфігурованих профілів.
- Немає розширеної логіки імпорту/експорту та batch-операцій.

## Покриті теми курсу
- SOLID: розділення шарів, інверсія залежностей, окремі інтерфейси.
- UML: class diagram, sequence diagram.
- Колекції та LINQ: пошук, групування, агрегація, збірка статистики.
- Обробка помилок: валідація, винятки, контролювання стану.
- Persistence: асинхронне збереження та відновлення стану.
- Тестування: unit та integration tests, negative scenarios.

## Частково покриті теми
- Performance: базовий аналіз LINQ, без системних benchmark тестів.
- Патерни: репозиторій, сервіс, стратегія; але не повний набір декораторів/просі.
- Архітектурні діаграми: є діаграми, але без деталізованих deployment-діаграм.
- Асинхронність: один асинхронний persistence flow, але не повні async batch сценарії.

## Дорожня карта після релізу
1. Впровадити SQL persistence / EF Core.
2. Додати REST API або веб-інтерфейс.
3. Розширити coverage threshold та quality gate у CI.
4. Додати audit та логування операцій.
5. Реалізувати кешування доступу до book/copy data.
