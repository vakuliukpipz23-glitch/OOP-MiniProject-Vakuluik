# Iteration 2 Plan - Lab 35

## Гілка
lab35-business-and-persistence

## Мета ітерації
Розвинути baseline з Lab 34: додати файлове збереження, бізнес-правила, запити та аналітику, зберігши архітектуру без перезапуску.

## Сценарії для реалізації
1. **Повернення та управління боргами**
   - існуючий сценарій позичення/повернення
   - додати блокування позичення при непогашеному боргу
2. **Пошук і фільтрація книг**
   - пошук за назвою, автором, категорією
   - аналітика за категоріями та найпопулярнішими книгами
3. **Збереження стану у файл**
   - JSON persistence через `IDataStore<LibrarySnapshot>`
   - збереження/відновлення реального стану книг, копій, читачів і позичень

## Що залишаємо без змін
- модель домену: `Book`, `Copy`, `Patron`, `BorrowRecord`, `OverduePolicy`
- контракти репозиторіїв `IBookRepository`, `IPatronRepository`, `IBorrowRepository`
- базову консольну архітектуру та основні сервіси

## Точки розширення
- `IOverduePolicy` як стратегія розрахунку штрафів
- `IDataStore<T>` для підмінного persistence
- `LibraryQueryService` для LINQ-запитів і аналітики
- репозиторні інтерфейси як місце для майбутніх SQL або XML реалізацій

## Ризики

- тісна зв'язка між DTO snapshot і доменними сутностями при відновленні
- обробка пошкодженого JSON-файлу
- дата/час у тестах для прострочення
