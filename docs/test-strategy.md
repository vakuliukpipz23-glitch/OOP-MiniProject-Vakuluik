# Тестова Стратегія

## Мета
Гарантувати стабільність бізнес-логіки та зменшити ризики при зміні функціоналу через чітке розділення тестових шарів.

## Підходи
- **Модульні тести**: перевірка окремих доменних класів та сервісів без залежностей від диску
- **Інтеграційні тести**: перевірка збереження чи відновлення стану з реальним файловим сховищем
- **Негативні сценарії**: відстеження очікуваних винятків при некоректних даних або бізнес-правилах

## Критичні області для тестування
- Сутності домену: валідація в конструкторах, зміна статусів копій, розрахунок штрафів
- Сервіси: позичення, повернення, реєстрація і оновлення даних
- Репозиторії: дублікат, відсутні записи, оновлення
- Персистенція: читання/запис JSON-файлу, пошкоджені дані, відновлення стану
- Обробка помилок: звичні та бізнес-винятки

## Інструменти
- `xUnit` для виконання тестів
- `coverlet.collector` для збору покриття коду
- `GitHub Actions` для автоматичного запуску тестів на кожному push

## Стратегії
- Тримати модульні тести швидкими та ізольованими
- Використовувати реальний файл лише там, де потрібна перевірка персистенції
- Додавати негативні випадки поруч із позитивними сценаріями
- Оновлювати тестову матрицю при зміні доменної моделі
