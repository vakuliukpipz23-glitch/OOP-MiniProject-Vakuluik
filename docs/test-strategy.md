# Test Strategy

Мета: забезпечити надійну перевірку критичних сценаріїв бібліотечної системи, виявити регресії та протестувати fault handling для persistence.

Критичні сценарії
- Реєстрація та оновлення патрона
- Реєстрація книги та оновлення категорії
- Запозичення і повернення книг (включно з overdue)
- Збереження та відновлення стану з файлу
- Блокування запозичення при наявності боргу

Складні для тестування місця
- Файловий I/O (приклад: пошкоджений JSON, права доступу)
- Стан агрегатів при частковому відновленні (rehydrate)
- Сценарії із послідовними асинхронними операціями

Mocks vs Integration
- Використовувати mocks для: зовнішніх залежностей, таймерів, симуляції I/O помилок у юніт-тестах.
- Використовувати реальну інтеграцію для: persistence (файлові тести у тимчасових директоріях), повних сценаріїв від створення до збереження й повторного завантаження.

Негативні сценарії
- Пошкоджений/порожній файл JSON
- Відсутність файлу (новий запуск) — коректний старт
- Повторні спроби зберегти під час блокування файлу
- Некоректні дані (дублікати ISBN, некоректні ідентифікатори)

Метрики
- Кількість unit / integration тестів
- Code coverage (opencover)
- Час виконання тестів

Порядок дій
1. Рефакторинг seams для mock-ів
2. Написати юніт-тести для домену
3. Додати інтеграційні файлові тести
4. Підключити coverlet та генерацію звітів
5. Додавати тести для fault handling

Примітка: тестова стратегія оновлюватиметься після виконання початкових тестів і аналізу ризиків.
