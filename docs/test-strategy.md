# Test Strategy — Lab 36

Мета: створити систему, яка має чіткий quality gate, перевіряє persistence і fault-handling, та забезпечує захист ключових бізнес-сценаріїв.

## Критичні сценарії
- Реєстрація книги та управління копіями
- Видача і повернення книги (borrow / return)
- Обчислення прострочених штрафів
- Збереження та відновлення стану з файлової системи
- Обробка пошкоджених або відсутніх даних при завантаженні

## Складні для тестування ділянки
- File I/O: потрібні інтеграційні тести з тимчасовими файлами
- Дати / overdue logic: потрібні контрольовані стани (Rehydrate)
- Відновлення стану: взаємодія між книгами, копіями, читачами та записами позик

## Де потрібні мокі, а де реальна інтеграція
- Unit tests: сервіси (`BookService`, `BorrowService`, `PatronService`, `LibraryQueryService`) із in-memory репозиторіями
- Integration tests: `JsonFileDataStore<LibrarySnapshot>` + `LibraryPersistenceService` на реальному тимчасовому файлі

## Негативні сценарії
- Пошкоджений JSON-файл => перевірка винятка
- Файл відсутній => відновлення має повернути пустий стан або контрольований результат
- Відсутні залежності при restore (book/patron/copy missing)
- Дублікат при реєстрації книги
- Повернення вже поверненої книги

## Які сигнали якості
- Наявність чіткого розшарування бізнес-логіки і I/O
- Покриття критичних шин і negative cases
- Інтеграційна перевірка з повним save/load циклом
- CI, який запускає тести і збирає coverage
