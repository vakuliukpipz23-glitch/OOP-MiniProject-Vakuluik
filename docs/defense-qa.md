# Defense Questions & Answers

## 1. Які рефакторинги були найважливішими саме перед релізом?
- Розділення залежностей через інтерфейси репозиторіїв.
- Винесення persistence в `LibraryPersistenceService`.
- Впровадження окремих сервісів для бізнес-логіки.
- Додавання тестів на негативні сценарії.

## 2. Чим FINAL_REPORT.md відрізняється від README.md?
- README містить інструкції зі встановлення, запуску та короткий огляд.
- FINAL_REPORT пояснює архітектурні рішення, компроміси, ризики та що було зроблено для релізу.

## 3. Які теми курсу ваш проєкт демонструє найкраще?
- Шарова архітектура та SOLID.
- Колекції/ЛІНК/групування у звітності.
- Персистентність через абстракцію `IDataStore<T>`.
- Тестування unit + integration та negative scenarios.

## 4. Які теми довелося добирати окремими розширеннями?
- Async batch import/export залишився на майбутнє.
- Audit logging/Observer не реалізовано.
- REST API/веб інтерфейс також відкладено.

## 5. Яке архітектурне рішення ви б змінили, якби починали проєкт заново?
- Виніс би UI з `Program.cs` у окремі класи для тестованості.
- Додав би `IDateTimeProvider` для стабільного тестування часових сценаріїв.
- Розділив би репозиторій та persistence на окремі рівні з adapter/facade.

## 6. Як ви доводите, що проєкт готовий до захисту?
- CI проходить успішно з .NET 10 та coverage.
- 63 теста покривають критичні сценарії та негативні випадки.
- Документація оновлена і відповідає коду.
- Збереження/відновлення стану працює у реальному сценарії.

## 7. Які ризики ще залишаються?
- Відсутність багатопотокового тестування для репозиторіїв.
- JSON persistence без схеми.
- Простий консольний UI як базовий інтерфейс.
