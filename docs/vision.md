# Документ Видіння - Система Управління Бібліотекою

## Назва Проекту
**Система Управління Бібліотекою (СУБ)**

## Постановка Задачі
Бібліотекам потрібен ефективний спосіб управління інвентарем книг та операціями позичання. Наразі бібліотекарам не вистачає цифрової системи для:
- Відстеження доступних книг та їхніх копій
- Обробки запитів на позичання книг від відвідувачів
- Управління реєстрацією та інформацією про відвідувачів
- Розрахунку штрафів за прострочене повернення
- Управління резервуваннями книг, коли копії недоступні

Ця система має за мету цифровізувати основні операції бібліотеки та створити основу для майбутніх розширень.

## Цільові Користувачі
1. **Бібліотекарі** - Персонал, який управляє книгами, обробляє позичання/повернення та керує реєстрацією відвідувачів
2. **Відвідувачі/Читачі** - Члени бібліотеки, які позичають книги та хочуть відстежувати позичені видання
3. **Адміністратори Бібліотеки** - Менеджери, які потребують моніторингу операцій бібліотеки та генерування звітів

## Основні Сценарії Використання

### Сценарій 1: Реєстрація Нового Відвідувача
**Дійова особа:** Бібліотекар  
**Передумова:** Відвідувач новий для бібліотеки  
**Основний Потік:**
1. Бібліотекар відкриває систему та вибирає "Зареєструвати Відвідувача"
2. Вводить інформацію про відвідувача (ім'я, електронна пошта, телефон)
3. Система перевіряє дані та присвоює унікальний ID відвідувача
4. Відвідувач зареєстрований та готовий позичати книги

### Сценарій 2: Позичення Книги
**Дійова особа:** Бібліотекар (від імені відвідувача)  
**Передумова:** Відвідувач зареєстрований; книга доступна  
**Основний Потік:**
1. Бібліотекар шукає книгу за назвою або ISBN
2. Система показує доступні копії
3. Бібліотекар вибирає копію та ініціює позичення
4. Система записує дату позичення та дату повернення (30 днів)
5. Підтвердження позичення зареєстроване

### Сценарій 3: Повернення та Розрахунок Штрафів
**Дійова особа:** Бібліотекар  
**Передумова:** Відвідувач позичив книгу(и)  
**Основний Потік:**
1. Бібліотекар шукає відвідувача
2. Переглядає список позичених книг з датами повернення
3. Бібліотекар позначає книгу як повернену
4. Якщо затримка: система розраховує штраф (0.50 за день)
5. Показує підтвердження повернення з урахуванням штрафів

## Нефункціональні Вимоги

1. **Читабельність та Обслуговуваність Коду**
   - Чітке та зрозуміле називання
   - Добре задокументовані публічні API
   - Дотримання принципів SOLID
   - Максимальна довжина методу: 20 рядків

2. **Тестованість**
   - Доменна модель повністю тестована (без залежностей)
   - Паттерн Repository для доступу до даних
   - Мінімум 80% покриття тестами для доменної логіки
   - Без жорстких залежностей від зовнішніх систем

3. **Відмовостійкість та Обробка Помилок**
   - Коректна обробка невалідних вхідних даних
   - Зрозумілі повідомлення про помилки для користувача
   - Відновлення після неповних операцій
   - Перевірка на межах домену

4. **Розширюваність**
   - Архітектура на основі сервісів для простого додавання функцій
   - Дизайн на основі інтерфейсів для репозиторіїв та сервісів
   - Підготовка до майбутнього шару збереження (SQL, файли тощо)
   - Підготовка до API або веб-інтерфейсу без змін коду
